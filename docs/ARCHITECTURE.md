# 架构

## 部署与代码边界

仓库只发布 `nodebridge` 一个程序，用 `hub` / `node` 命令选择模式。两种模式共享配置编码、TLS、WebUI、状态数据和隧道协议。

```text
cmd/nodebridge/       CLI、模式选择、信号处理
internal/app/        hub/node、账号、配对、在线记录
internal/store/      hub 嵌入式 bbolt 存储
internal/transport/  yamux 配置和 TCP 数据转发
internal/telemetry/  本机 SSH 探测与 nvidia-smi
internal/web/        内嵌 HTML/CSS/JavaScript
scripts/             安装、卸载和跨架构打包
docs/                架构、迁移和运维
```

前端为原生 HTML/CSS/JavaScript，不需要独立构建工具或 CDN。节点维护页用于首次配对、诊断、本机 SSH/TCP 转发开关和端口授权；正式账号、节点管理和 SSH 命令入口在 hub。

## 配对流程

1. 安装 hub，生成证书、嵌入式数据库和随机管理员账号。
2. 管理员指定节点名称，生成一次性随机 256 位邀请令牌，保存其 SHA-256 摘要及 15 分钟有效期。
3. 编码为 `nodebridge://pair/<base64url-json>`，内容只有 hub HTTPS 地址、邀请令牌和证书 SHA-256 指纹。链接不是供浏览器打开的页面，需要粘贴到节点 UI 或 CLI。
4. 节点按指纹验证 hub 的 TLS 证书，通过 `POST /api/enroll` 兑换邀请。
5. hub 在存储事务和端口分配互斥锁保护下实际监听端口，建立节点记录，并消费邀请。任何分配/保存失败都会回滚，释放监听器，保留邀请。
6. hub 返回唯一节点 ID、独立认证凭证和固定公网端口。hub 保存凭证摘要，节点保存原始凭证和指纹，文件权限为 `0600`。
7. 节点携带 ID 和 Bearer 凭证主动建立 `/api/connect` WebSocket 连接。

网络在兑换成功后丢失响应或节点无法保存配置时，邀请已经消费。管理员移除刚创建的离线节点并重新生成链接；不无限重复发放同一凭证。

## 穿透协议

控制台 HTTPS 和节点连接共用同一个端口。WebSocket 提供 TLS 连接上的双向字节流，yamux 在其中建立独立数据流，避免自行实现复用与背压。

- 类型字节 `1`：hub 到 node 的 SSH 数据流。节点只能连接 `127.0.0.1:<ssh_port>`，先返回单字节就绪结果，再转发 TCP。
- 类型字节 `3`：hub 到 node 的 TCP 服务流，跟随 2 字节大端目标端口。node 根据本机允许列表和 TCP 暂停开关验证，再连接 `127.0.0.1:<port>`；单字节 ACK 后复用原始 TCP 传输，不改写 HTTP 或 WebSocket。
- 类型字节 `2`：node 到 hub 的 JSON 状态。每次上报使用一个短生命周期的数据流，限制大小和读取时长。
- yamux 每 10 秒保活；节点每 10 秒收集状态；45 秒无有效上报则节点状态过期。
- 节点重连使用 1–30 秒退避及随机延迟；新会话取代同一节点的旧会话。
- 每节点最多同时接受 128 个公网 SSH 连接，每 TCP 代理最多 128 个并发连接，节点也限制同时处理的数据流。

SSH 流量经 VPS 中继，SSH 自身的协议加密和 Linux 账号鉴权保持有效。hub 登录权限控制管理界面；公网 SSH 端口最终由节点的 SSH 服务验证密钥/密码。

相关实现依据：[coder/websocket NetConn](https://pkg.go.dev/github.com/coder/websocket#NetConn)、[yamux 协议与库](https://github.com/hashicorp/yamux)。

## 暂停 SSH 转发

暂停只作用于 SSH 数据流，保持 WebSocket/yamux 管理连接和状态上报。hub 在接入 SSH 连接时检查全局与单节点开关，并追踪活动 TCP 连接；暂停时关闭范围内的连接。node 在连接本机 SSH 前检查本机开关，并追踪 SSH 流和本机连接；暂停时关闭这些流与连接。两侧的检查和登记与暂停操作使用同一互斥锁，避免并发新连接绕过暂停。

`PUT /api/forwarding` 的 JSON 为 `{"paused":true}` 或 `{"paused":false}`，hub 要求管理员会话，node 使用原有回环维护页的 Host/Origin/请求头保护。hub 的 `PUT /api/nodes/{id}/forwarding` 控制单节点。全局、单节点、本机三个开关独立，恢复一处不会解除另一处的暂停。node 在状态中上报 `forwarding_paused`，hub 的 SSH 就绪状态同时检查三个开关；GPU 与在线状态仍然展示。

hub 两类开关通过数据库事务保存，node 通过配置文件原子替换保存。旧版本未提供的字段默认 false，不改变原有配对和端口；公网监听器继续占用固定端口，暂停时接受到的连接被关闭而不会转发。

## 状态与持久化

hub 使用一个 bbolt 文件存储 schema v1 的账号、会话、邀请、节点、TCP 代理、有限审计和每日采样结果，不需要数据库服务。当前规模定位为少量到数十个节点，状态事务采用 JSON 快照，便于审查与备份。

所有持久化更新以 bbolt 事务提交。节点配置以同目录临时文件、fsync 和 rename 更新。端口在初次分配和 hub 重启时实际监听；重启遇到外部端口占用时保留原端口并显示错误，避免静默改变 SSH 地址。

GPU 数据是可观测性信息。缺少 `nvidia-smi` 或数据为 N/A 时明确显示未知，不据此宣称 GPU 已被业务分配或空闲。

每日在线记录每 30 秒采样一次，只统计 hub 运行期间的观察结果。hub 停机时不会补造数据，该比例不能直接作为持续在线 SLA。最新状态在内存中，最近观察时间和每日统计落库；实时完整 GPU 数据不会逐次落库。

## 鉴权

- 首次管理员由机器本地生成，禁止通过公开注册抢占管理员。
- 密码使用 bcrypt，限制为 10–72 字节。
- 会话使用随机令牌，数据库只保存摘要，24 小时有效；每账号最多 10 个并行会话。
- 浏览器使用 HttpOnly、Secure、SameSite=Strict Cookie；写操作要求同源和自定义请求头。
- 请求权限从数据库读取当前账号角色；重置密码、角色变更和删除账号会撤销该账号已有会话。
- 节点使用每台独立凭证，删除节点立即关闭监听和会话；不使用全节点共享内部密钥。
- 本地维护页只允许回环监听，校验 Host、Origin 和自定义请求头，防止跨站配对及 DNS rebinding。
- 默认没有远程命令执行、任意目标转发或公开节点管理 API。

TLS 证书更换会改变指纹，旧节点不能自动信任新证书，需要重新配对。支持浏览器可信证书的方式是部署时替换 hub 数据目录中的证书/私钥，在接入节点前完成；当前没有 ACME 自动续期流程。

## 后续扩展

如果恢复旧版 Docker 实例、GPU 配额、计费功能，集中放在同一仓库中，以额外类型的授权请求协议扩展节点执行能力。需要单独定义 owner/admin 权限、资源事务、幂等生命周期事件和计费数据模型；禁止直接开放任意命令或把管理密钥传给浏览器。

当前不兼容旧 Python HTTP API，也不自动导入旧 SQLite/PostgreSQL 数据。首次部署采用独立端口/数据目录，通过并行验证后切换入口。

## TCP 服务授权与代理

本机 `POST /api/tcp-ports` 添加允许的服务端口，`DELETE /api/tcp-ports/{port}` 撤销。只接受回环目标，最多 16 个端口，不允许配置的 SSH 或维护端口。权限沿用节点维护页的回环 Host/Origin/自定义请求头保护，配置原子保存；撤销时立即关闭该端口的数据流。本机暂停使用 `PUT /api/tcp-forwarding`，不改变 SSH 开关。

hub 的 `/api/proxies` 及 `PUT /api/proxies/{id}/forwarding`、`DELETE /api/proxies/{id}` 只允许管理员操作。创建前要求节点在线且上报目标端口授权。端口分配与节点配对共用互斥锁、端口池、数据库事务和实际监听检查，失败回滚；重复节点/目标端口拒绝创建。最多 100 个额外 TCP 代理。

状态上报新增 TCP 支持标记、允许端口及本机服务就绪信息。旧节点默认不支持 TCP，SSH 协议保持兼容。真正建立服务流时节点再次验证允许列表，不依赖 hub 的状态缓存；暂停/撤销与数据流登记使用同一互斥锁，防止连接绕过暂停。

SSH、单 TCP 代理、本机全部 TCP 开关各自独立，暂停会断开范围内的活动连接，保留监听、管理会话和端口。删除代理关闭监听并回收端口；删除节点在同一事务中删除全部相关代理。重启恢复原端口及暂停状态，监听冲突可释放端口后重试。

当前仅提供 TCP 中继。HTTP 的公网客户端链路不自动升级为 HTTPS；服务账号鉴权由 Overleaf 等后端负责，hub 的 Cookie 登录只保护管理 API。域名、Nginx 和 ACME 后续另行实现。
