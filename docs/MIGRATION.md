## 基线确认

2026-09-30 检查两个旧仓库，当前分支均为 `simple-tunnel-platform`。

现有 README 和运行代码的实际功能是账号控制台、节点状态/GPU 展示以及固定节点 SSH 穿透。父目录 AGENTS 的 Docker/GPU 实例、配额、卡时计费属于另一阶段的历史规划。NodeBridge 按用户确认的单程序双模式方案实现当前分支，不把历史规划标记为已迁移。

## 切换方法

1. 在 VPS 使用不同于旧服务的 Web 端口和 SSH 端口池部署 NodeBridge。例如旧版占用 `9999/7000/30000`，新版使用 `9443/30010–30019`。
2. 在一台节点安装 node 模式，使用旧服务相同的本地 SSH 端口 22 即可，两种转发可并行访问同一 sshd。
3. 通过配对接入，验证实际外网 SSH 登录、大文件传输、hub/节点重启恢复、GPU 状态和管理员权限。
4. 新建需要的控制台账号，保持节点已有 Linux 用户和 SSH 密钥。
5. 把正式入口切换到 NodeBridge；逐节点迁移。
6. 完成真实 VPS/节点验收后再停用旧 Python 和 FRP 服务。保留旧数据备份，用于回滚。

本次代码开发不改动旧仓库、不停用旧服务、不自动修改云防火墙、不把旧用户数据库当作已导入。
